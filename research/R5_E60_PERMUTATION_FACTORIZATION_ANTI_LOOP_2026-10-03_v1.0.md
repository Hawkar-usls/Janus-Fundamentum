## 1. Universality of the `I+P+Q` normal form

Let `A` be a simple square `0/1` matrix with every row sum and every column sum
exactly `3`.  Regard it as the biadjacency matrix of a 3-regular bipartite graph
between row vertices and column vertices.

By Hall/Konig, every regular bipartite graph has a perfect matching.  Remove one
perfect matching; the remainder is 2-regular bipartite, hence a disjoint union of
even cycles and decomposes into two further perfect matchings.  Thus

```text
A = P0 + P1 + P2
```

for permutation matrices `P0,P1,P2` with disjoint supports.

Relabel the column side by `P0^{-1}`.  Then

```text
A  ~  I + P + Q.
```

Therefore arbitrary noncommuting `P,Q` are not a special sparse subclass to be
closed by exploiting factorization alone.  This is a normal form for the full
simple square cubic bipartite carrier.

Consequence: any claimed universal polynomial algorithm based only on the fact
that `P,Q` are permutations must contain genuinely new global information; the
mere 1-factorization cannot be the leverage, because every hard target already
has one.

## 2. Alternating `P/Q` cycles are real but not independent blocks

In the bipartite graph with row and column copies kept distinct, retain only the
`P` and `Q` matching edges.  Every vertex then has degree `2`, so this subgraph is
a disjoint union of alternating even cycles.

The mistake is to identify those cycles with independent components of the full
matrix.  The identity matching `I` adds one more edge incident to every row and
every column and can connect many distinct `P/Q` cycles.

The companion checker freezes an explicit `n=12` example:

```text
p(i)=i+1 mod 12,
q(i)=i+5 mod 12.
```

For this pair:

```text
P+Q bipartite subgraph : 4 alternating cycles, each on 6 bipartite vertices;
full I+P+Q graph       : 1 connected bipartite component;
<p,q> action           : 1 orbit on all 12 indices.
```

Hence a DP run independently on the `P/Q` cycles is not a universal algorithm.

## 3. Correct orbit decomposition

The subgroup generated by the two index permutations

```text
G = <p,q>
```

partitions the common index set into orbits.  Each orbit is preserved by `I,p,q`,
so after simultaneous row/column ordering, `A` is block diagonal by these orbits.
Thus the orbit decomposition itself is valid.

However an orbit is a connected component of the Schreier graph generated by
`p,q` (and equivalently their inverse arcs).  With two arbitrary permutations,
that graph can have branching/degree greater than two after forgetting arc labels;
it is not generally a cycle.

In the same `n=12` fixture above, the single Schreier component has undirected
degree `4` at every vertex.  So the implication

```text
orbit => cycle => constant-state linear DP
```

is false in general.

A valid necessary consequence from E58/E59 does survive: if an orbit `O` is an
independent matrix block and a global cap word exists, that block must itself hit
its cap, so

```text
|O| divisible by 3
```

is necessary for every orbit.  Divisibility is only a filter, not a solver.

## 4. Why the direct flow / degree-2 factor is not equivalent

The cubic bipartite incidence graph has row vertices and column-variable vertices.
A true Exact-One solution chooses a subset `S` of column variables.  If a column
`j` is selected, all three incidences of that column are active simultaneously;
if it is not selected, none are.  Every row must see exactly one selected column.

This all-or-none column coupling is the hard condition.

If instead one asks for a bipartite subgraph with degree `2` at every row and
column, the problem collapses: the union of the `P` and `Q` matchings is already
such a 2-factor for every `I+P+Q` input.

The frozen E58 `UNSAT9` instance therefore has

```text
Exact-One                  : UNSAT,
degree-2 row/column factor : trivially FEASIBLE (take P+Q).
```

So ordinary flow / b-matching using only degree constraints is a strict
relaxation and cannot certify Exact-One.

## 5. SWITCH4 and FREE8 are relation orbits, not cycle lengths

R5 E55 defines

```text

FREE8   = {0,1}^3
```

as local claw-relation families around a conflict vertex (up to cube symmetry).
The numerals `4` and `8` count allowed local 3-bit transversals.

They do **not** mean a 4-vertex cycle and an 8-vertex cycle.  Therefore scanning
`P/Q` for cycles of lengths `4` and `8` is not a correct detector for the E55
hardness-localization types.

## 6. Ternary representation: exact correction

For a Boolean vector `x`, define over `F_3`

```text
r = 1 + x,
```

so `r_i` is `1` or `2` and hence has full support.

For a cubic row, the possibilities are:

```text
# ones in x   row sum of r mod 3
0             0
1             1
2             2
3             0
```

Therefore

```text
integer Exact-One Ax=1
iff
exists r in (F_3^*)^n with A r = 1 over F_3.
```

But binary parity alone

```text
A x = 1 over F_2
```

allows either one or three ones per row.  It is **not** equivalent to the ternary
full-support equation.  The canonical counterexample is `x=1`: it satisfies the
binary parity equation for every cubic row, while its corresponding `r=2*1` has
ternary row sum `0`, not `1`.

Thus the F3 handle remains valid precisely as an Exact-One representation, not as
a reformulation of the whole E56 parity coset.
